==================================================

- no incorrect CONVERTED status

Use a PostgreSQL transaction.

==================================================
4. ORDER CREATION TRANSACTION
==================================================

Order creation must happen inside a database transaction.

The transaction must revalidate ALL critical values immediately before creating the order.

Do NOT trust the Phase 7 checkout validation result as permanently valid.

Inside the final order-creation transaction revalidate:

1. Authenticated customer identity
2. Active cart ownership
3. Cart status
4. Cart contains at least one item
5. Cart/store relationship
6. Store status
7. Store service-pincode eligibility
8. Selected customer address ownership
9. Product existence
10. Product active state
11. Product availability
12. Product/store relationship
13. Category/store relationship where relevant
14. Current product prices
15. Current stock constraints
16. Current delivery fee
17. Current minimum order value
18. Current subtotal
19. Current total
20. COD payment mode

Only after all validations pass may the order be inserted.

==================================================
5. CART LOCKING
==================================================

Prevent duplicate orders from the same cart caused by concurrent requests.

When placing an order:

- lock the relevant cart row
- verify it is still ACTIVE
- lock/revalidate relevant cart items/products as appropriate
- prevent a second concurrent order from converting the same cart

If one request successfully converts the cart:

ACTIVE → CONVERTED

a second request must fail safely.

Do not create duplicate orders.

Do not use an elaborate distributed locking system.

Use PostgreSQL transactions/row locks appropriately.
