IMPLEMENTATION TASK — MOBILE-FIRST RESPONSIVE UI FOR ALL PORTALS

Make the existing Local Supermarket Marketplace application fully responsive and comfortable to use on mobile phone screens.

The current application is primarily designed around desktop/tablet layouts. We need the screens to properly fit common mobile widths without horizontal scrolling, overlapping elements, clipped text, or unusable navigation.

IMPORTANT:
- This is a RESPONSIVE UI task.
- Do not create a separate mobile application.
- Reuse the existing React Native / React Native Web / shared UI architecture.
- Preserve all existing functionality and business logic.
- Do not change database/business rules unless absolutely required for responsive UI.
- Do not modify authentication, Master Catalog, products, stock, cart, checkout, orders, or delivery logic.
- Do not deploy.
- Do not run automated browser tests.
- Do not fix unrelated pre-existing TypeScript errors.
- Use the existing shared design system.
- Make the minimum safe changes required.

==================================================
1. TARGET MOBILE EXPERIENCE
==================================================

The application must work comfortably on common mobile widths, including approximately:

- 320px
- 360px
- 375px
- 390px
- 414px

The UI must not depend on a specific phone width.

At mobile widths:

- No unintended horizontal scrolling.
- No content clipped off-screen.
- No overlapping buttons.
- No text cut off unnecessarily.
- Forms fit within the viewport.
- Cards fit within the viewport.
- Buttons remain tappable.
- Inputs remain usable.
- Navigation remains accessible.
- Tables become mobile-friendly layouts.
- Modals fit within the screen.
- Long content can scroll vertically.
- Keyboard input must remain usable.

==================================================
2. CUSTOMER PORTAL — MOBILE
==================================================

Make the Customer Portal mobile-first.

### Header

On mobile:

- Use a compact header.
- Logo/store branding should fit.
- Search should remain accessible.
- Avoid excessive header height.
- Do not allow header items to overflow horizontally.

### Global Search

The existing single global search must fit the mobile width.

Example:

[ 🔍 Search products or stores ]

The search field should use nearly the available width with appropriate side padding.

Do not place unnecessary controls beside it on very small screens.

### Category browsing

Category controls should stack vertically when necessary.

For example:

Search
[ Search products or stores ]

Browse by category
[ All categories ▼ ]

No horizontal overflow.

### Product Cards

Product cards must fit within the mobile viewport.

Ensure:

- Product image does not overlap text.
- Product name wraps correctly.
- Price remains visible.
- Quantity controls remain usable.
- Add button remains visible.
- Long product names do not push buttons outside the card.
- Cards have consistent spacing.

Do not create excessively large cards.

### Product Details

Product detail page should stack sections vertically:

Image
↓
Product information
↓
Variant selection
↓
Price
↓
Quantity
↓
Add to Cart

Buttons should use appropriate mobile width.

### Cart

Cart should fit the mobile viewport.

No desktop-style wide cart layout on small screens.

Items should stack vertically where necessary.

Checkout/action buttons should remain visible and easy to tap.

### Saved Items

Saved Items must be mobile-friendly.

Each saved item should fit within the screen and allow:

- View product
- Remove saved item
- See price
- See availability

### Settings

Settings should become a simple vertical mobile list/form.

Do not use wide desktop cards.

8. BUTTONS — MOBILE
==================================================

Buttons must remain comfortably tappable.

Use a reasonable minimum touch target.

Do not make buttons tiny simply to fit more content.

For action groups:

Desktop:
[Save] [Cancel]

Mobile:
[Save]
[Cancel]

when side-by-side buttons would be cramped.

==================================================
9. MODALS / DIALOGS
==================================================

All modals must fit inside the mobile viewport.

On mobile:

- Modal width should be nearly full width with side margins.
- Content should scroll vertically if long.
- Buttons should remain accessible.
- Close button should remain visible.
- Do not create a modal wider than the viewport.

This applies to:

- Product details
- Confirmation dialogs
- Delete/archive confirmations
- Document upload
- Password reset
- Admin actions
- Vendor actions

==================================================
10. TABLES
==================================================

Inspect every existing table.

At mobile widths, choose the most appropriate approach:

Preferred:
Convert table rows to cards.

Acceptable when the table genuinely needs many columns:
Allow horizontal scrolling ONLY inside the table container.

Do NOT allow the entire application page to become horizontally scrollable.

==================================================
11. IMAGES
==================================================

All images must be responsive.

Use:

max-width: 100%

and appropriate aspect-ratio/object-fit behavior.

Prevent:

- stretched images
- overflowing images
- images covering buttons/text
- fixed desktop dimensions

Product images should maintain consistent aspect ratios.

==================================================

Do not reintroduce those problems.

- Vendor/Admin sidebars do not create unnecessary horizontal scrolling.

Avoid fixed heights that cause content clipping.
