IMPLEMENTATION TASK — ADMIN VENDOR DOCUMENT VIEWING

We have identified an important missing integration:

A Vendor can successfully upload their required/optional documents from:

Vendor Portal → Documents

However, those uploaded documents are currently NOT visible from:

Admin Portal → Vendors → Vendor Details/Profile

The Admin Vendor management area must be extended so authorized Admin users can view the documents submitted by that Vendor.

IMPORTANT:
- Inspect the existing Vendor Documents implementation first.
- Reuse the existing Vendor Documents database model, metadata, storage, and APIs.
- Do NOT create a second document table.
- Do NOT create a second document storage system.
- Do NOT change the Vendor upload workflow unless required.
- Do NOT change Customer, Product, Master Catalog, Stock, Cart, Order, or Delivery logic.
- Do NOT deploy.
- Do NOT run automated browser tests.
- Do NOT fix unrelated pre-existing TypeScript errors.
- Keep the change focused only on Admin visibility of Vendor documents.

2. DOCUMENT STATUS
==================================================

Show the current status of each document.

Possible states:

- Not Uploaded
- Uploaded

If the existing Vendor Documents implementation already has additional statuses, reuse those statuses rather than creating a duplicate status model.

Clearly distinguish:

MANDATORY
OPTIONAL

Show:

Mandatory Documents: X / 4

Do not count optional documents toward mandatory completion.

==================================================
3. ADMIN VIEW DOCUMENT
==================================================

Admin should have a:

[View]

action for uploaded documents.

When Admin clicks View:

Open the document securely.

For images:

- JPG/JPEG
- PNG
- WebP

show an appropriate preview.

For PDFs:

open/display the PDF using the existing application/browser-supported approach.

Do NOT expose the underlying private storage path directly if the existing storage architecture supports secure/signed access.

==================================================
4. ADMIN AUTHORIZATION
==================================================

Only authorized Admin users may view Vendor documents.

Do NOT allow:

- Customer to view Vendor documents
- Vendor A to view Vendor B's documents
- Delivery Partner to view Vendor documents

Admin authorization must be enforced server-side.

Do not rely only on hiding the UI.

==================================================
5. REUSE EXISTING DOCUMENT API/MODEL
==================================================

Inspect the existing endpoint:

GET /api/vendor/documents

and the existing Vendor Documents service/model.

Do NOT duplicate this logic unnecessarily.

Create an Admin-authorized document retrieval endpoint/service only if the existing endpoint cannot safely support Admin access.

For example, if appropriate to the current architecture:

GET /api/admin/vendors/:vendorId/documents

The endpoint must:

1. Verify Admin authentication.
2. Verify ADMIN role/server-side.
3. Resolve the requested Vendor/Store.
4. Retrieve that Vendor's document metadata.
5. Return only the requested Vendor's documents.
6. Provide secure viewing access when requested.

Do not return documents belonging to any other Vendor.

==================================================
6. STORAGE SECURITY
==================================================

Vendor documents are sensitive.

Especially:

- Aadhaar
- PAN
- FSSAI

Do NOT make Vendor documents public.

Do NOT change the existing private storage policy.

Admin document viewing should use secure access consistent with the existing Vendor Documents storage architecture.

Do not expose permanent public URLs.

If signed URLs are already used, reuse the existing secure mechanism.

==================================================
7. DOCUMENT METADATA
==================================================

Display useful metadata already stored by the Vendor Documents implementation, such as:

- Document type
- Upload status
- Original filename, if appropriate
- Uploaded date
- Last updated date
- Current version

Do not expose unnecessary storage internals.

Do not display storage paths.

Do not expose internal IDs unnecessarily.

==================================================
8. REPLACED DOCUMENTS
==================================================

If the Vendor replaces a document:

Admin should see the CURRENT active document.

Example:

FSSAI License
Current document
Uploaded: 08 Oct 2026
[View]

Do not accidentally show an obsolete version as the current document.

If the existing implementation maintains document history, preserve it.

Do not delete or modify document history just to implement Admin viewing.
