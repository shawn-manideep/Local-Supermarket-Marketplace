1. CRITICAL PHASE 9 RULE
--------------------------------------------------

PHASE 9 IS A QA / RELEASE READINESS PHASE.

Do NOT make broad feature changes.

Do NOT redesign architecture.

Do NOT add new business features.

Do NOT introduce new product requirements.

Do NOT start deployment.

Do NOT modify production.

Do NOT create an Admin Portal.

Only make a code change if testing identifies a concrete defect that prevents an approved requirement from working correctly.

For every defect found:

1. Identify the root cause.
2. Explain the impact.
3. Make the smallest safe correction.
4. Add a regression test.
5. Re-run affected tests.
6. Re-run relevant regression tests.

If no defect is found:

DO NOT modify code merely for the sake of making changes.
