PHASE 2 — GLOBAL SEARCH

Verify that Vendor Master Catalog search returns the populated Master Products.

Search MUST be global.

Category must remain optional.

A vendor must be able to search:
- product name
- brand
- relevant product details

without knowing the category.

Category is only a filter.

Do not restrict search to the currently selected category.

PHASE 3 — CUSTOMER GLOBAL SEARCH

Customer global discovery should also work across the Master Catalog.

Customer search must not require category selection.

However, purchasing remains store-specific:
- only eligible stores for the customer's saved-address pincode
- only products actually available in those stores
- price and purchasability remain vendor/store/variant-specific

Do not expose:
- exact stock
- SKU
- external codes
- internal timestamps
- unnecessary internal IDs

PHASE 4 — FIX "CAN'T FIND A PRODUCT?"

Current problem:
The form makes Master Category appear mandatory and exposes technical "Discovery attributes" / JSON-style input.

Change the UX.

Vendor should be able to create a missing product without manually knowing the platform category.

Use a normal form:

Product Name — required
Brand — optional
Product Type / Details — optional
Description — optional
Image — optional

Do NOT expose JSON fields to vendors.

Do NOT require the vendor to select a category before duplicate checking.

After entering the product information:

1. Run global duplicate detection.
2. Show possible existing Master Products.
3. If one matches, allow vendor to select it instead.
4. If none matches, allow creation of the new Master Product.
5. Categorization should be handled by the platform/admin/catalog process rather than forcing the vendor to know the taxonomy.

If the system cannot confidently classify a newly created Master Product, use an internal pending/unclassified state rather than forcing an incorrect category.

PHASE 5 — DUPLICATE PROTECTION

Before creating a new Master Product, search globally.

Do not check only within a selected category.

Check existing active and archived Master Products.

If an exact duplicate exists:
- do not create another Master Product
- direct vendor to the existing Master Product
- if archived, show restoration/reuse guidance

For possible matches:
- show them to the vendor
- require explicit confirmation that none matches before creating a new Master Product

Maintain the existing concurrency-safe creation/reuse logic.

PHASE 6 — MASTER DATA DELETION

There must be NO DELETE action for:
- Master Categories
- Master Products

Do not add DELETE endpoints or UI buttons.

Use:
Active
Archived

Archive must preserve:
- Master ID
- vendor mappings
- store listings
- historical orders
- historical snapshots
- audit history

Archiving prevents new selections but does not physically remove the Master record.
