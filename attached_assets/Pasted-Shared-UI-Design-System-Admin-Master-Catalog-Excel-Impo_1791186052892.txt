Implement an Admin-only Excel Import/Export workflow.

- Browse Current Catalog

- Upload Updated Excel
- Validate uploaded Excel
- Preview changes

- Import/version history
The Excel file becomes a convenient bulk-management interface for the platform Master Catalog.

CRITICAL DATA OWNERSHIP RULE
The Excel Master Catalog must NEVER overwrite vendor-specific commercial information.
Do NOT import/update these vendor-owned values through the Master Catalog Excel:
- Vendor price
- Vendor stock
- Vendor availability
- Vendor SKU
- Vendor external code
- Vendor-specific selling configuration
- Vendor-specific promotions
- Vendor-specific inventory
- Vendor-specific variant commercial values
These remain owned by the individual vendor/store.
MASTER PRODUCT ID MUST BE IMMUTABLE
Master Product ID is the stable identity of the Master Catalog product.
Admin may edit the product's canonical information.
Admin must NOT be allowed to change:
MP001 → MP999

The existing Master Product ID must remain unchanged.
If an uploaded Excel file contains a modified/nonexistent/invalid Master Product ID, reject it rather than interpreting it as a rename.
Do not merge products automatically.
Do not silently remap products.
CATEGORY ID RULE
Master Category IDs must also remain stable.
If an existing category ID is changed or an invalid category ID is referenced:
- reject the affected row
- show a clear validation error
- do not silently create a different category
Do not use category names alone as a dangerous identity replacement when an existing ID is available.
NEW PRODUCTS / CATEGORIES
If the current Master Catalog architecture supports creation of new canonical products/categories through Admin, the Excel workflow may support adding new records.
However:
- Existing IDs must remain immutable.
- New IDs must be generated safely by the system/database.
- Do not trust arbitrary IDs from Excel for newly created records if the current architecture uses UUID/generated IDs.
- Do not create duplicate canonical products.
- Do not automatically merge similar products based only on names.
If the current implementation does not support Excel creation of new records safely, initially restrict Excel import to updating existing records and report this clearly.
Do not invent a risky creation mechanism.
EXCEL UPLOAD FLOW
Uploading Excel must NOT immediately modify the database.
The workflow must be:

      ↓

VALIDATION
Validate at minimum:
Workbook structure
- Required sheets exist.
- Required columns exist.
- Unexpected critical structural problems are reported.
- Empty workbook is rejected.
Product validation
- Master Product ID exists for existing records.
- No duplicate Master Product IDs.
- Required product fields are valid.
- Category ID exists.
- Status is valid.
- No invalid references.
Category validation
- No duplicate Master Category IDs.
- Existing category IDs cannot be changed.
- Required fields are present.
- Status is valid.
Data integrity
Reject malformed or ambiguous imports.
Do not partially apply a bad workbook.
