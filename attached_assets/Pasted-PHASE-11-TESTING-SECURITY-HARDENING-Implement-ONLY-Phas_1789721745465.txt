Inspect:

==================================================
2. SECURITY REVIEW — AUTHENTICATION
==================================================

Review all authenticated routes.

Verify:

- unauthenticated requests are rejected
- Supabase bearer tokens are validated correctly
- expired/invalid tokens are rejected
- role resolution is server-side
- customer role cannot become vendor/admin through request data
- vendor role cannot become admin through request data
- admin role cannot be self-assigned
- no public admin signup exists
- no public role-assignment endpoint exists

Inspect authentication middleware carefully.

Do not replace Supabase Auth.

==================================================
3. AUTHORIZATION REVIEW
==================================================

Perform an endpoint-by-endpoint authorization review.

Classify every API route as:

- public
- customer
- vendor
- admin
- shared authenticated

For every protected endpoint verify:

authenticated identity
    ↓
role
    ↓
resource ownership/scope
    ↓
authorized operation

Never rely only on frontend restrictions.

==================================================
4. IDOR SECURITY REVIEW
==================================================

Look specifically for insecure direct object references.

Test or structurally verify:

Customer A → Customer B address
Customer A → Customer B order
Customer A → Customer B cart
Customer A → another customer's order item

Vendor A → Vendor B store
Vendor A → Vendor B category
Vendor A → Vendor B product
Vendor A → Vendor B order
Vendor A → Vendor B order item

Non-admin → admin resources

Admin → unauthorized mutation paths

Client-provided IDs must never override authenticated ownership.

==================================================

==================================================

Verify vendor isolation across ALL vendor resources:

- store
- service pincodes
- operating hours
- categories
- products
- carts if applicable
- orders
- order items
- order history

Vendor A must never read or modify Vendor B's resources.

Inspect both:

- API authorization
- database RLS

6. CUSTOMER ISOLATION
==================================================

Verify customers can access only their own:

- profile
- addresses
- carts
- orders
- order items
- order history
- delivery information

Test ID substitution wherever IDs are accepted.

==================================================
7. ADMIN BOUNDARIES
==================================================

Verify:

- admin endpoints require admin role
- vendor cannot call admin endpoints
- customer cannot call admin endpoints
- admin cannot accidentally create broad public mutation paths
- no generic admin order mutation exists
- no arbitrary status assignment exists

Admin privileges should remain intentional.

==================================================
8. REQUEST VALIDATION
==================================================

Review every API input schema.

Use Zod consistently.

Look for:

- missing validation
- permissive schemas
- unknown fields being accepted
- client financial fields
- arbitrary status values
- arbitrary role values
- arbitrary store ownership
- malformed UUIDs
- invalid dates
- negative amounts
- negative quantities
- oversized strings
- unreasonable pagination values

Reject unexpected protected fields where appropriate.

==================================================
9. MASS ASSIGNMENT REVIEW
==================================================

Inspect all POST/PATCH APIs for accidental mass assignment.

A client must NOT be able to submit protected fields such as:

- customer_id
- owner_user_id
- store_id
- role
- commission_rate
- commission_amount
- status
- created_at
- updated_at
- financial snapshots
- delivery snapshots

unless explicitly authorized by the endpoint.

10. SQL / DATABASE SECURITY
==================================================

- no unsafe table/column interpolation

Pay particular attention to:

- search/filter endpoints
- date filters
- pagination
- store filters
- order IDs
- product IDs
- category IDs
