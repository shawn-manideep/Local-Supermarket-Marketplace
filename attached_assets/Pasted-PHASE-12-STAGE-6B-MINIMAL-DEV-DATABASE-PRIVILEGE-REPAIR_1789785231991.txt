PHASE 12 — STAGE 6B: MINIMAL DEV DATABASE PRIVILEGE REPAIR

Stage 6A is approved.

The exact root cause of the Stage 6 RLS failure has been established:

- Supabase Data API is reachable.
- Customer A's valid JWT reaches PostgreSQL.
- RLS is enabled.
- Existing RLS policies have the intended ownership logic.
- `authenticated` has public schema USAGE.
- `authenticated` lacks SELECT privilege on:
  - public.customers
  - public.customer_addresses
- PostgreSQL therefore returns:
  42501 permission denied for table

OBJECTIVE

Apply the smallest possible DEV-only database privilege repair so the authenticated Supabase role can perform SELECT against:

- public.customers
- public.customer_addresses

After the privilege repair, rerun the relevant live RLS verification.

IMPORTANT ARCHITECTURAL RULE

Do NOT weaken RLS.

The required combination must remain:

table SELECT privilege
+
applicable RLS policy

Do NOT grant broader access than necessary.

Do NOT grant:
- anon SELECT
- PUBLIC SELECT
- service-role changes
- unrestricted access to other tables

Do NOT modify existing RLS policies.

==================================================
BEFORE REPAIR
==================================================

Inspect the existing database/migration privilege conventions.

Determine whether the privilege should be represented in a new migration so the DEV database state remains reproducible.

Do NOT modify migration files that have already been applied.

If a new migration is required, create the smallest forward-only migration necessary.

Do not rewrite or reorder existing migrations.

Use the project's existing migration conventions.

==================================================
REQUIRED REPAIR
==================================================

Grant only:

authenticated → SELECT → public.customers

authenticated → SELECT → public.customer_addresses

Do not grant INSERT, UPDATE, or DELETE unless existing application requirements demonstrably require them for this specific Stage 6 test.

Do not grant access to unrelated tables.

Do not change schema ownership.

Do not change RLS policies.
