CUSTOMER APP UI/UX REVAMP + VERIFIED BUG FIXES

I reviewed the actual Customer application in a browser recording.

The current customer UI is functional in several areas, but visually and experientially it is not acceptable for a consumer-facing grocery marketplace.

DO NOT rebuild the backend or change the business architecture.

We need a professional, modern, customer-friendly grocery marketplace UI inspired by the information hierarchy and usability patterns of established Indian grocery apps such as Zepto, Blinkit and BigBasket.

IMPORTANT:
Use these products only as UX/design inspiration.
Do NOT copy their branding, logos, colors, exact layouts, assets, or proprietary designs.

The goal is:
- modern
- clean
- visually engaging
- mobile-first
- easy for non-technical customers
- strong visual hierarchy
- grocery-shopping focused
- polished enough for a real MVP demo

TECHNICAL CONSTRAINTS:
- Keep the existing Expo + React Native + TypeScript architecture.
- Keep existing backend APIs.
- Keep Supabase Auth.
- Keep existing database schema.
- Keep RLS/security.
- Keep business rules.
- Do not introduce a new UI framework unnecessarily.
- Do not create fake functionality.
- Do not replace working APIs with mock data.
- Do not change order/business logic unless required to fix a verified bug.
- Preserve the existing customer functionality.

PART 8 — FIX CUSTOMER CANCEL ORDER
==================================================

This is a VERIFIED FUNCTIONAL BUG from browser testing.

Current behavior:
- Order is PLACED.
- "Cancel order" button is visible.
- Clicking it does not visibly cancel the order.

Investigate the existing implementation.

Do NOT weaken backend authorization or lifecycle rules.

Customer cancellation is allowed only while order status is PLACED.

Expected behavior:

Cancel Order
→ confirmation dialog
→ user confirms
→ existing customer cancellation API
→ HTTP success
→ order status becomes CANCELLED
→ status timeline updates
→ cancel button disappears
→ order list updates

If the API fails:
- show a useful user-facing error
- keep the order in its actual server status

Add a regression test for the UI/API interaction if the existing test architecture supports it.

PART 10 — PHONE VALIDATION
==================================================

This is another VERIFIED BUG.

Current phone field accepts:
- more than 10 digits
- non-numeric characters

Fix both frontend and backend validation.

For Indian mobile numbers:

- exactly 10 digits
- digits only
- first digit must be 6, 7, 8 or 9

Frontend:
- numeric input mode
- maxLength=10
- filter/reject non-digit characters
- clear validation message

Backend:
- enforce the same business validation
- never rely only on frontend validation

Do not change unrelated profile fields.
