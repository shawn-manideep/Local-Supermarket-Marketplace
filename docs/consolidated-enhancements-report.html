Consolidated implementation and verification

Development-only implementation. No production deployment, Publish action, OTP, SMS, WhatsApp or paid notification provider was introduced. Existing authentication identities were preserved.

Operational effect: All 7 existing Vendor stores now require current document and bank approval before catalog operations or new orders. There are currently no submitted bank records. Vendors must submit genuine details and Admin must review them; no approvals were fabricated. Existing order/delivery fulfillment remains available under existing authorization rules.

Missing background-push configuration

The project has no complete configured push delivery path. Closed-portal notifications need a supported platform/browser choice, permission/opt-in handling, service-worker/PWA setup for web, private per-user subscriptions, server-side push dispatch and credentials such as a Web Push VAPID key pair managed through Secrets. Subscription cleanup, role/activity checks and real-device background/closed tests are also needed. Native push would require its platform-specific setup. No credentials were requested and no paid provider was added in this implementation.

Manual browser checklist

  1. Sign in as an existing Vendor: Profile/Documents/Bank Details and existing Orders remain accessible, while Catalog/new orders stay blocked before approval. Confirm no fee settings appear; save/read back valid coordinates and check invalid or half-entered coordinates are rejected.
  2. Submit required documents with no Vendor photo. Confirm missing Labour License blocks submission. Submit bank information, including an account number with leading zeroes; verify masking. As Admin, explicitly reveal, reject with a reason, then approve corrected current submissions. Confirm another Vendor cannot view them.
  3. Confirm approved active Vendor catalog access. Change an approved mandatory document or bank field and verify catalog/new-order eligibility returns to pending review without preventing existing fulfillment.
  4. In Customer checkout, test Add New Address in English and Telugu. Cancel once and confirm the cart is unchanged; save a valid address, confirm immediate selection and later address-book persistence.
  5. Keep Vendor portal open while placing a development order. Check the banner/View Order, sticky Accept/Reject, automatic Preparing history and direct Mark as Ready. Verify every date filter and compare a downloaded PDF with the full filtered authoritative orders, not just the displayed page.
  6. Open two active Partner sessions and claim one Ready offer simultaneously. Only one should win. On a phone, deny/cancel capture and confirm pickup is blocked; capture/preview/recapture, simulate failed upload, retry, then pick up. Confirm unrelated Partner/Customer photo denial and Admin authenticated viewing.
  7. Complete delivery through Out for Delivery and Delivered. Compare own daily PDF with Admin individual/all reports for the India-calendar day, IDs, amounts and timestamps; retries must not duplicate deliveries.
  8. Do not expect notifications after closing the portal. Background push remains unconfigured.
